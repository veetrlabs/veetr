title: "Administrators"
description: "Manage users, scoped roles, creation requests, and account security."
---

Administrators manage access across Veetr. This is separate from being a series manager or a responsible skipper. Administrative operations require authenticator verification.

## Open user management

1. Sign in at [Account](/account/).
2. Open **Users**.
3. If prompted, set up your authenticator by scanning the QR code.
4. Enter the current six-digit code and choose **Verify**.

After scanning, find the Veetr entry in the authenticator’s code list. Scanning alone does not complete verification. Keep the QR code and authenticator codes private.

## Find and edit a user

Search by email. Pending boat invitations also appear in the list with a **Pending invitation** label; an invitation is not yet an accepted account membership.

Open a registered user to edit access on their dedicated page. Review the email and the existing memberships before making changes.

## Assign the appropriate role

Choose **Series** or **Boat**, select the named entity, and choose the role. Confirm the access change in the confirmation dialog.

- **Series manager** configures that series and its races.
- **Referee** operates racing within that series.
- **Skipper** manages that boat and its crew.
- **Crew** participates in that boat’s tracking.

Removing an entry removes the selected membership, not every permission that user holds. The user may still have access through ownership or another role.

## Manage account-wide access

User controls include administrator access, permission to create series, account suspension, and session revocation. Read the confirmation carefully: these actions have a wider effect than changing one series or boat membership.

The system protects the last administrator from removal. Use boat handover for a change of responsible skipper rather than trying to remove the owner as an ordinary team member.

## Review requests and history

Use **Requests** to approve or reject series creation requests. Approval lets an account create series; it does not make them an administrator.

Review **Access audit history** when checking who changed access and what changed. Verify the exact user, scope, and role before granting privileges, and remove access when it is no longer needed.
